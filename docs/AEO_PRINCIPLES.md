# AI가 우리를 어떻게 소개하는가 — AEO 원칙

**정립: 2026-08-11**

> 사람들이 검색창 대신 AI에게 먼저 묻기 시작했습니다.
> 그때 HebronGuide가 답에 나오느냐 — 그것이 AEO(Answer Engine Optimization)입니다.

---

## 먼저, 영업 주장과 사실을 갈라 둡니다

이 원칙은 한 AEO 서비스 대표의 인터뷰에서 출발했습니다.
**유용한 구조적 통찰이 있었지만, 파는 사람의 말이므로 나눠서 받습니다.**

| 주장 | 우리 판단 |
|---|---|
| "AI 유입 전환율 50%, 일반의 5배" | **검증 불가.** 영업 숫자로 본다. 우리 숫자로 확인하기 전엔 인용하지 않는다 |
| "3개월 만에 세 배" | 같음 |
| AI는 페이지를 전부 읽지 않고 구조·메타 위주로 본다 | **타당** |
| 일관된 고유명사(엔티티)가 중요하다 | **타당** |
| 뾰족하고 검증 가능한 근거가 인용된다 | **타당** |
| 폐쇄적 플랫폼은 AI가 가져가기 어렵다 | **타당** |

---

## 우리가 이미 하고 있던 것

`llms.txt` 가 **190줄**로 이미 있었습니다. 엔티티 정의까지 되어 있습니다.
영상이 말한 것을 상당 부분 먼저 하고 있었습니다.

**문제는 만들지 않은 것이 아니라, 낡은 것이었습니다.**

---

## 🚨 2026-08-11에 발견한 것 — 이것이 이 문서의 이유입니다

`llms.txt` 는 **자동 갱신 대상이 아니었고, 2026-07-09에 멈춰 있었습니다.**

그 안에 이런 문장들이 남아 있었습니다:

| llms.txt가 AI에게 말하던 것 | 실제 |
|---|---|
| **"2030년 500개 도시 목표"** | **8월 2일에 지운 문장.** *"야망이고 허황된 껍질 광고"* |
| "78개 도시" | 82개 |
| **"파트너** 교회·업소 등록" | 8월 2일에 없앤 말. 오해의 진원지 |
| "**검증한 출처·날짜와 함께**" | `verified_at` 기록이 **없다** |

> ### 화면에서 지운 문장이 llms.txt에 남으면, AI는 그것을 인용합니다.
>
> 목사님은 지웠는데 **AI는 계속 말하고 있었습니다.**

**AEO의 첫걸음은 새 콘텐츠를 만드는 것이 아니라, AI가 이미 읽고 있는 문서를 사실에 맞추는 것입니다.**

### 재발 방지

`scripts/update-city-count.js` 의 갱신 대상에 `llms.txt` 를 넣었습니다.
배포마다 자동으로 숫자가 맞춰집니다.

## 원칙 다섯

### 1. 화면에서 지운 말은 llms.txt에서도 지운다

문안을 고칠 때 **반드시 함께 확인**합니다.
[`WORDS_OPEN_DOORS.md`](WORDS_OPEN_DOORS.md) 의 점검 명령에 llms.txt를 포함시킵니다.

```bash
grep -n "파트너\|500개\|2030\|기본 무료\|프리미엄" llms.txt
```

### 2. 뾰족한 근거만 쓴다 — 형용사는 인용되지 않는다

영상의 핵심입니다. *"우리 치과 친절해요"* 는 AI가 쓸 수 없습니다.

| ❌ 형용사 | ✅ 인용 가능한 사실 |
|---|---|
| 한인이 **검증한** 정보 | 시애틀 한인 교회 **28곳**의 교단·연락처 |
| **믿을 만한** 가게 | (업소 3개 — **지금은 쓰지 않는다**) |
| **풍부한** 정착 정보 | 공항 → 한인 밀집 지역 대중교통 경로, 운전면허 절차 |
| **따뜻한** 환대 | 이번 주 금요일 저녁 함께 식사하는 모임 **3곳** |

> **없는 것을 뾰족하게 쓸 수는 없습니다.**
> 업소가 3개면 "믿을 만한 가게"라고 쓰지 않습니다. 그게 AEO의 진짜 규율입니다.

### 3. 이름을 세트로 고정한다

AI는 `HebronGuide` 와 `헤브론가이드` 를 다른 것으로 볼 수 있습니다.

```
항상 함께:  HebronGuide(헤브론가이드, hebronguide.com)
✗ 금지:    우리 플랫폼 · 저희 서비스 · 본 사이트
✗ 금지:    헤브론 (단독 — 다른 헤브론이 많다)
```

### 4. 답하고 싶은 질문을 먼저 적는다

영상의 가장 좋은 통찰입니다. 콘텐츠를 쓰기 전에 **질문을 정합니다.**

HebronGuide가 답이 되어야 할 질문 (우리가 실제로 가진 것 기준):

```
✅ 답할 수 있다 — 교회 959곳, 도시 82개
   "시애틀 이사 가는데 한인 교회 어디가 좋아?"
   "○○ 도시에 한인 교회 있어?"
   "미국 처음인데 운전면허 어떻게 따?"

✅ 우리만 답할 수 있다 — 아무도 안 하는 것
   "시애틀에 막 왔는데 이번 주에 혼자 밥 안 먹을 방법 없을까?"

❌ 답하지 못한다 — 쓰지 않는다
   "시애틀 한인 맛집 추천해줘"   (업소 3개)
   "중고 가구 어디서 사?"        (없음)
```

### 5. 구조화 데이터는 아직 없다 — 다음 순서

`application/ld+json` **0개**입니다.
교회 목록은 구조화하기 가장 좋은 자산이지만, **지금은 만들지 않습니다.**
→ [`NICHE_STRATEGY.md`](NICHE_STRATEGY.md) "지금 하지 말아야 할 것"

## 우선순위 — 정직하게

[`NICHE_STRATEGY.md`](NICHE_STRATEGY.md) 에 **"SEO·광고 집행 ❌ — 와도 앉을 자리가 없다"** 고 적었습니다.
AEO도 같은 것 아니냐는 물음이 당연합니다. **다릅니다.**

```
SEO·광고 집행   = 돈과 시간을 들여 사람을 끌어온다     → 지금 아니다
llms.txt 고치기 = 하지 않은 약속을 멈춘다              → 지금 해야 한다
```

**llms.txt에 "2030년 500개 도시"가 남아 있던 건 유입 문제가 아니라 정직성 문제였습니다.**

| 지금 | 나중 (세 교회가 돌기 시작한 뒤) |
|---|---|
| ✅ llms.txt를 사실에 맞춘다 (완료) | 구조화 데이터(JSON-LD) |
| ✅ 자동 갱신에 연결 (완료) | 답할 질문별 콘텐츠 |
| ✅ 답할 질문 목록 정리 (이 문서) | robots.txt에 AI 크롤러 명시 환영 |
