## 비전 — 왜 Hebron AI 인가

전 세계 한인 디아스포라는 각자의 지역에 흩어져 있지만, **"내가 나그네 되었을 때 너희가 영접하였다"**(마 25:35)의 환대로 하나로 묶입니다. 지금의 ChatGPT·Claude·Gemini는 **일반 지식**은 뛰어나지만, **"린우드 H Mart"·"애넌데일 한인 치과"·"뉴몰든 한인교회"** 같은 **지역·커뮤니티 특화 지식**에서는 자주 틀립니다.

**Hebron AI**는 **디아스포라 특화 지식**을 모아, 가장 신뢰할 수 있는 **"가장 가까운 식탁"을 안내하는 전용 AI**입니다. 혼자가 아닙니다. 제2·3 브레인(멀티 LLM)과 손잡고, **한어권과 영어권 사이의 다리**를 가장 자연스럽게 놓습니다.

---

## 왜 가능한가 — 지금 쌓이는 데이터

HebronGuide는 이미 **디아스포라 특화 데이터**를 매일 쌓고 있습니다:

| 데이터 유형 | 현재 소스 | 용도 |
|---|---|---|
| **도시별 FAQ 294개** | `city-content.json` (21개 도시 × 14 FAQ) | 지역별 정착 지식 |
| **글로벌 레지스트리** | `lounge-sites.json` (12+곳, 수시 확장) | 한인 커뮤니티·단체·업소 창구 |
| **교회 디렉토리** | Supabase `churches` 테이블 | 지역별 교회·교단·사역 태그 |
| **환대 지도** | `cities.json` (81개 도시 좌표) | 글로벌 지역 핀 |
| **공공 사실 데이터** | 영사관·학군·DMV·세금·의료 통역 체계 | 공공 서비스 정보 |
| **환대 사례** | arrive.html·voices.html·설교·목회 글 | 환대 신학·실천 |

이 모든 데이터가 **단일 소스**로 모이면, 디아스포라 전용 AI의 **학습·검색 베이스**가 됩니다.

## 4단계 로드맵

### Phase 1 · 레지스트리 수집 (지금 — 2026-10-17 진행 중)

**목표**: 신뢰할 수 있는 모든 사이트·단체·업소 디렉토리를 **큐레이션**해서 하나의 레지스트리로.

**지금 상태**:
- `hebronguide/public/lounge-sites.json` — JSON 기반 데이터 분리 (수시 확장 가능)
- `lounge.html` — JSON 로드·카테고리 필터·한/영 토글
- 12곳 등재 (10개 커뮤니티 + 공식 조직 + 한인회 placeholder)

**다음 액션**:
- 한인회·상공회의소 URL 수집·확장 (대표님 네트워크 활용)
- 각 지역 교회·업소 디렉토리 세부 확장
- "추천 폼" 운영 (mailto → 저가 검증 → JSON 추가)

---

### Phase 2 · 다국어 UI (근미래 — 2026 Q4)

**목표**: 한어권·영어권을 **동시에** 서비스.

**지금 상태**:
- `lounge.html` — 한/영 토글 이미 작동 (localStorage 저장)
- `/arrive.html`·`/map.html`·city FAQ — 일부 한/영 병기

**다음 액션**:
- 모든 핵심 페이지에 한/영 토글 확장
- `/{city}/` React SPA에 `?lang=en` 쿼리로 영어 UI 전환
- i18n 데이터 분리 (city-content.json 영어 번역 필드 추가)
- SEO: `hreflang` 태그 완비 — 영어 사용자가 Google 영어 검색으로 유입

---

### Phase 3 · RAG 벡터 DB (중기 — 2027 Q1~Q2)

**목표**: 모든 데이터를 **임베딩** → 벡터 검색으로 "질문-답" 즉시 응답 베이스.

**기술 선택지**:

| 옵션 | 장점 | 단점 | 비용 |
|---|---|---|---|
| **Supabase pgvector** | 지금 쓰는 Supabase 그대로 · DB 통합 | 성능 한계 (수만 벡터까지 OK) | 무료 티어 넉넉 |
| **Pinecone** | 벡터 전용 · 성능 최상 | 외부 서비스 · 월 과금 | 무료 티어 월 10만 벡터 |
| **Weaviate** | 오픈소스 · 자가 호스팅 가능 | 운영 부담 | 자가 호스팅 무료 |
| **Supabase pgvector 추천** | Hebron 생태계와 자연스럽게 통합 | 지금 선택이 가장 안전 | $0 (무료 티어) |

**데이터 임베딩 흐름**:
```
city-content.json ─┐
lounge-sites.json ─┤
churches 테이블   ─┤─ 임베딩 모델(OpenAI text-embedding-3 또는 Voyage AI) ─ Supabase pgvector
교회·arrive·voices─┤
공공 사실(영사·DMV)┘
```

**다음 액션** (Phase 3 시작 시):
- 임베딩 파이프라인 설계 (`scripts/embed-corpus.mjs`)
- Supabase pgvector 테이블 설계
- 질문-답 검색 테스트 (예: "린우드 한국 소아과?")

### Phase 4 · Hebron AI 챗봇 (장기 — 2027 Q3~Q4)

**목표**: 사용자가 자연어로 질문 → **디아스포라 특화 답변**.

**멀티 LLM 아키텍처** ("제2·3 브레인"):

```
사용자 질문
   │
   ▼
Hebron 벡터 DB 검색 (RAG, 지역 특화 지식 꺼내기)
   │
   ├─ 제1 브레인: Claude Sonnet/Opus (현재 Anthropic — Hebron 톤·환대 신학 반영 최상)
   ├─ 제2 브레인: GPT-4o/5 (대안 응답·크로스 체크)
   └─ 제3 브레인: Gemini (한국어 자연스러움 보강·멀티모달)
   │
   ▼
세 응답 합의·요약 (또는 사용자 선택)
   │
   ▼
Hebron AI 응답
```

**왜 멀티 LLM?**
- **환각 방지** — 세 모델이 다 틀리기 어려움
- **각 모델 강점 활용** — Claude 환대·GPT 범용·Gemini 한국어·멀티모달
- **비용 분산** — 한 공급자에게만 묶이지 않음
- **대표님 지시 "통크게"** — 하나의 프레임에 갇히지 않는 아키텍처

**UI 통합**:
- 각 페이지 우측 하단 "**Hebron에게 물어보기**" 플로팅 챗봇
- `/ask/` 전용 페이지
- 응답에 **출처 명시** (어느 FAQ·어느 라운지 사이트에서 온 정보인지)

**비용 설계**:
- 무료 티어: Hebron 교인·일반 사용자 — Haiku 중심 (저가)
- 유료 티어: 심층 분석 — Sonnet·Opus (후원·구독)
- NanuriWeb 교회 사이트 번들: Hebron AI 챗봇 포함 (교회 플랫폼 가치 상승)

## 저작권·개인정보 원칙 (CLAUDE.md 지침 준수)

- **공공 사실만** 임베딩 (주소·전화·공개된 데이터)
- **사용자 게시물·창작 콘텐츠는 임베딩 금지** (seakorean·missyusa 게시글 등)
- **각 사이트 저작권 존중** — Hebron은 **큐레이터**이지 **복제자**가 아님
- **개인정보 유출 방지** — 질문자 데이터 저장 최소화·익명화
- **응답에 출처 명시** — "미주 중앙일보 ASK미국에 유사 질문", "주시애틀 총영사관 공지 참고"
- **오류 시 책임 분리** — "AI 응답은 참고용. 공식 결정은 각 기관 공식 창구에서."

## 큐레이터 선언

> HebronGuide는 가장 한국적인 환대 신학과 가장 열린 미국적 플랫폼 문화를 함께 담습니다.
> 혼자 모든 것을 가지려 하지 않습니다. 먼저 길을 낸 커뮤니티를 존중하며,
> **동서양을 잇는 다리**가 됩니다.
>
> 모든 데이터는 결국 **한 사람 한 사람의 식탁**으로 흘러가야 합니다.
> AI는 식탁을 **대체**하지 않고 **차릴 수 있도록** 돕습니다.
