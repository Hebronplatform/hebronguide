## 2. 송곳 목표 — 이것 하나에 맞춘다

> **낯선 도시에 도착한 한인이, 첫 주에 혼자 밥 먹지 않게 한다.**

모든 화면·기능·문장은 이 질문을 통과해야 남습니다.
**"이것이 새로 온 사람을 첫 주 안에 한 사람·한 식탁·한 교회 앞에 데려다주는가?"**
통과하지 못하면 빼거나 한 단계 뒤로 숨깁니다. 기능이 많다고 섬기는 것이 아닙니다.

## 3. 새 정착자의 눈으로 걷기

아래 네 사람은 **설계를 위한 가상 인물**입니다(실제 사례처럼 쓰지 않습니다). 각 사람이 되어 지금 사이트를 직접 걸어 보십시오. 1면 `index.html` → 도시 선택 → 앱 홈 → 필요한 것을 찾을 때까지 몇 번 눌렀는지, 어디서 막혔는지, 어디서 길을 잃었는지 기록합니다.

| 가상 인물 | 처지 | 가장 먼저 필요한 것 |
|---|---|---|
| 가. 주재원 가족 | 아이 둘, 도착 사흘 전, 집·학교·운전면허 | 도착 전 준비 목록, 학군, 첫 주 할 일 |
| 나. 유학생 | 혼자, 교회 다닌 적 없음, 외로움 | 또래와 밥 먹을 자리, 부담 없는 첫 만남 |
| 다. 60대 부모 | 자녀 따라 이주, 영어 어려움 | 한국어로 된 병원·보험·도움 전화, 한인 교회 |
| 라. 비신자 직장인 | 교회엔 관심 없음, 일과 생활이 급함 | 생활 정보, 사기 경보, 믿을 만한 이웃 |

시간 순서로도 걷습니다: **도착 전 → 첫날 → 첫 주 → 첫 달 → 90일 → 다음 사람의 안내자.**

## 5. 만들어 낼 것 (이 순서, 이 형식)

**① 세 줄 요약** — 무엇을 남기고, 무엇을 빼고, 새로 온 사람에게 무엇이 달라지는가.

**② 걸어 본 기록** — 가상 인물 넷 × 시간 여섯 단계. 각 칸에 "지금 몇 번 눌러 닿는가 / 막힌 곳 / 빈 곳". 추측이 아니라 실제로 열어 본 결과만 씁니다.

**③ 필요 지도** — 표: 단계 | 필요 | 지금 있는 화면·페이지 | 빈 곳 | 우선순위(상·중·하).

**④ 전체 목록 분류** — 화면 14개, 정적 페이지 94개, 리다이렉트 176개, api 12개를 하나도 빠짐없이 표로. 각각 **남김 / 합침 / 숨김 / 보관(99_Archive)** 중 하나와 그 이유(송곳 목표와의 관계). 지우기 전에 그것에 기대는 것(링크·리다이렉트·SW precache·build.sh·vercel.json·sitemap·llms.txt)을 함께 적습니다.

**⑤ 새 정보 구조** — 1면·도시 홈·아래 탭의 새 뼈대를 글자 와이어프레임으로.
  - 1면과 도시 홈 첫 화면: Primary 버튼은 **정확히 하나**. 5초 안에 "이게 뭔가 + 지금 뭘 누르나"가 보여야 함
  - 아래 탭은 4개 이하, 모든 흐름은 3단계 이하
  - 사람·식탁·교회가 화면 아래로 밀려나지 않게

**⑥ 화면별 설계** — 바뀌는 화면마다: 목적 한 줄 / 누구의 어느 단계 필요인가 / 첫눈에 보이는 것 / Primary 행동 하나 / 빼는 것.

**⑦ 옮기는 순서** — 작게, 되돌릴 수 있게 나눈 단계들. 단계마다:
  - 건드리는 파일 / 기대는 것 / 위험("# 영향 주의:" 형식) / 확인 방법(`npm run build` EXIT 0, `node scripts/link-check.mjs`, 배포 후 `ver.txt`와 라이브 화면) / 되돌리는 법
  - 첫 단계는 화면을 바꾸지 않는 것(죽은 링크·쓰지 않는 페이지 보관·리다이렉트 정리)부터
  - 일요일에는 배포하지 않음

**⑧ 하나뿐인 지표를 재는 법** — "이번 주 혼자 밥 먹지 않은 사람 수"를 개인을 추적하지 않고 세는 방법. 지금 요금제와 api 12개 한도 안에서.

**⑨ 목사님이 결정하실 것** — 번호 목록. 각 항목에 추천안 하나와 이유 한 줄.
