# 헤브론 신뢰 모델 — 등록 · 검증 · 책임 · 피드백

**정립: 2026-09-18 · 김성수 목사**

> 헤브론은 **교회 · 사업체 · 개인** 세 가지 등록을 받는다.
> **환대할 준비가 된** 교회, 사업체, 개인을 필요한 사람과 연결한다.
> 신원조사는 분명히 한다. 매칭 이후의 관계에 대해서는 법적 책임을 지지 않는다.
> 피드백을 받아 계속 개선해 나간다.
>
> **목적은 하나다 — 서로 믿고 환대하므로, 좀 더 밝고 푸른 세상을 만드는 것.**

이것이 헤브론의 비전이자 사명이다. 이 문서는 그것을 어떻게 지킬 것인가를 적는다.

---

## 1. 세 가지 등록 — 지금 상태

| | 등록 창구 | 검증 | 상태 |
|---|---|---|---|
| **교회** | `church-join.html` · `church-submit.html` | 실재 확인 · 이단 여부 | 창구 있음 |
| **사업체** | `biz-join.html` · `ad-request.html` | 실재 확인 | 창구 있음 |
| **개인** | **없다** | **없다** | **아직 문이 없다** |

세 가지 중 **개인만 없다.** 그리고 개인이 가장 위험하다.

---

## 2. "신원조사"는 하나가 아니다

세 가지를 한 단어로 묶으면 위험하다. **대상이 다르면 확인하는 것도 달라야 한다.**

### 1단계 — 실재 확인 (교회 · 사업체)

그것이 **정말 있는가.**

- 교회: 교단·협회 명부, 공개 홈페이지, 다른 교회의 확인
- 사업체: 사업자 등록, 면허(해당 업종), 실제 주소

공개 정보로 할 수 있다. **돈이 들지 않고 법적 제약도 없다.** 지금 바로 가능하다.

### 2단계 — 보증 (개인)

**누가 이 사람을 아는가.**

```
"어느 교회가 이 사람을 보증하는가"
```

이것이 헤브론의 진짜 힘이다. 배경조사 서비스는 돈만 있으면 누구나 산다.
**교회의 보증은 아무도 흉내 낼 수 없다.** 우리만 가진 것이다.

016 마이그레이션에 이미 설계되어 있다 — 교회 확인과 운영진 승인 **둘 다** 있어야 승인된다.

```sql
constraint housing_two_gates check (
  status <> 'approved'
  or (church_verified_at is not null and staff_approved_at is not null)
)
```

### 3단계 — 배경조사 (개인 · 특정 경우만)

범죄경력 조회다. **이것은 법이 규제한다.**

미국에서 배경조사를 받아 그 결과로 사람을 거절하면, 연방법(FCRA)상 의무가 생긴다.

- 조회 전 **별도 서면 동의**
- 거절 시 **사전 통지 + 보고서 사본 + 이의 제기 기회 + 사후 통지**
- 주(州)별 추가 규정 (워싱턴주 포함)
- 비용이 실제로 든다 (건당 수십 달러)

**하지 않겠다는 말이 아니다. 시작하면 끝까지 지켜야 하는 일이라는 뜻이다.**

---

## 3. 면책의 역설 — 반드시 알아야 할 것

약관에 "책임지지 않습니다"라고 쓰는 것은 필요하다. 그러나 **그것으로 끝나지 않는다.**

> **검증했다고 크게 말할수록, 면책은 약해진다.**

"우리가 확인한 사람입니다"라고 광고하면, 사람들은 그 말을 믿고 문을 연다.
사고가 났을 때 문제가 되는 것은 약관이 아니라 **우리가 한 그 말**이다.
카우치서핑이 무너진 자리가 정확히 여기다. ([PLATFORM_TRUST_PLAYBOOK.md](PLATFORM_TRUST_PLAYBOOK.md) S1)

### 그래서 규칙은 하나다

**우리가 실제로 한 것만, 그대로 말한다.**

| 쓰지 않는다 | 쓴다 |
|---|---|
| 검증된 안전한 사람 | ○○교회의 추천을 받았습니다 |
| 신원조사 완료 | 신분증과 연락처를 확인했습니다 |
| 헤브론이 보증합니다 | 헤브론은 소개하고, 만남은 두 분의 결정입니다 |

부풀리지 않으면 면책이 산다. 부풀리면 약관이 있어도 무너진다.

**변호사 검토가 한 번은 필요하다.** 나는 변호사가 아니다.
약관·면책·개인정보 처리방침은 개인 등록을 열기 전에 한 번 검토받아야 한다.

## 4. 개인 등록이란 무엇인가 — 식탁과 잠자리

2026-09-18 목사님이 정의하셨다. 개인 등록은 사람 명부가 아니다.

> 개인이 자기 집에서 **밥 한 끼를 대접한다.** 저렴한 값에, 자기 전통 음식으로.
> 혹은 **하룻밤 재워 준다.** 좋으면 며칠 연장하고, 아니면 그만둔다.
> **"그 집 안에 사람이 있다는 게 Airbnb와 다른 점이다."**

빈집을 빌려주는 임대가 아니라, 사람이 있는 집에 들이는 환대다.

**정본: [HOSPITALITY_TABLE_AND_STAY.md](HOSPITALITY_TABLE_AND_STAY.md)**

핵심만 옮기면 이렇다.

| | 단계 | 지금 |
|---|---|---|
| 1 | **식탁** — 밥 한 끼, 무료 | `gathering.html` 로 **이미 돌고 있다.** 호스트를 개인 가정까지 넓히면 된다 |
| 2 | **하룻밤** — 1박, 비용 나누기 | 면허·보험 확인 후 |
| 3 | **연장** — 2~29박 | 변호사 검토 후 |

**30박을 넘으면 손님이 세입자가 된다.** 호스트가 내보낼 수 없게 된다.
**29박 자동 종료를 코드로 막는다.** 호스트를 지키는 가장 중요한 장치다.

**식탁을 거치지 않고 잠자리로 가지 않는다.** 밥 한 끼 같이 먹어 보면 서로 안다.

## 5. 피드백 루프 — 시스템의 심장

별점보다 이것이 낫다. 이미 [PLATFORM_TRUST_PLAYBOOK.md](PLATFORM_TRUST_PLAYBOOK.md)에 적혀 있고, **아직 하나도 만들지 않았다.**

```
연결  →  만남  →  다음날 한 통  →  기록  →  다음 연결에 반영
                      ↑
              "어제 어떠셨어요?"
              답이 없는 것도 정보다
```

| | 무엇을 | 현재 |
|---|---|---|
| ① | **다음날 확인 연락 한 통** | 없음 |
| ② | **피해 신고 창구 한 곳** | 없음 |
| ③ | 비상 연락처 한 곳 | 없음 |
| ④ | 같은 전화·이메일 반복 등록 감지 | 없음 |

①과 ②가 전부다. 이 둘이 없으면 "계속 개선"은 말뿐이다.

## 6. 지금 막혀 있는 것 — 실측 (2026-09-18)

보고가 아니라 실제로 조회한 결과다.

| 확인한 것 | 결과 |
|---|---|
| 신청자 이메일·전화가 밖에서 읽히는가 | **읽힌다.** 익명 조회로 실명·이메일·전화가 그대로 나온다 |
| 015 (연락처 보호) | 미적용 |
| 017 (교회 목록 정리) | 미적용 — 시애틀에 주소가 이름 자리에 든 교회 4곳, 교단 본부 1곳 |
| 016 (이중 관문 테이블) | 테이블이 존재하지 않음 |
| Vercel 함수 자리 | **12개 중 12개 사용 — 꽉 찼다** |

### 두 가지가 실제 장애물이다

**하나 — 개인정보를 못 지키면서 신원조사를 할 수 없다.**
지금 이 순간 신청자 연락처가 밖에서 읽힌다. 신원조사를 논하기 전에 이것부터다.

**둘 — 새 기능을 넣을 자리가 없다.**
`submit-church.js` · `submit-listing.js` · `submit-form.js` · `submit-story.js` ·
`register-business.js` · `register-partner-church.js` — **여섯 개가 거의 같은 일을 한다.**
하나로 합치면 자리가 다섯 개 난다. 그래야 개인 등록이 들어갈 수 있다.

## 7. 순서

한 번에 하나씩. 앞이 끝나야 뒤가 가능하다.

```
1  015 적용          신청자 연락처 보호        (준비 완료 · 목사님 5분)
2  submit-* 6 → 1    API 자리 5개 확보          (개인 등록의 전제)
3  016 적용          교회 보증 + 운영진 승인    (이중 관문)
4  개인 등록 개설     여럿이 있는 자리만         (배경조사 없이, 보증으로)
5  다음날 한 통 + 신고 창구                      (피드백 루프의 최소 형태)
6  약관·면책 변호사 검토                         (단둘이 만나는 문을 열기 전)
7  배경조사                                     (6이 끝난 뒤에만)
```

**1번이 안 되면 나머지는 전부 위선이다.**
