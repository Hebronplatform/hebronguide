# 신뢰의 사슬 — 추천으로 이어지는 환대

> **"내가 나그네 되었을 때에 너희가 나를 영접하였다"** — 마태복음 25:35
>
> 정본. 2026-09-24 폴 김 목사 정립.
> 관련: [`PLATFORM_TRUST_PLAYBOOK.md`](PLATFORM_TRUST_PLAYBOOK.md) · [`FRAUD_DEFENSE.md`](FRAUD_DEFENSE.md) · [`GATHERING_SAFETY.md`](GATHERING_SAFETY.md)

---

## 한 문장

**출발지에서 도착지로 가는 사람을, 검증된 사람의 소개를 거쳐 환대자에게 잇는다. 그 모든 관계를 헤브론이 기록하고 이어 간다.**

낯선 사람이 없어야 한다. 모든 사람은 누군가를 통해 들어온다.

## 왜 이것이 우리만의 것인가

AI는 답을 준다. 우리는 **사람**을 준다.

관계는 시간에서만 나온다. 자료는 베낄 수 있어도 「누가 누구를 아는가」는 베낄 수 없다.
큰 회사가 돈으로 만들 수 없는 유일한 것이 이것이다.

그리고 새로운 발명이 아니다. 바울이 뵈뵈를 로마 교회에 추천한 편지(로마서 16:1-2)가
같은 구조다. 교회는 이천 년 동안 이렇게 사람을 보냈다.

## 성경이 정한 설계

각 줄은 취향이 아니라 근거다. 바꾸려면 근거부터 다시 봐야 한다.

| 성경 | 그래서 이렇게 만든다 |
|---|---|
| **레위기 19:34 · 신명기 10:19** — 나그네를 본토인처럼 여기라. 너희도 나그네였다 | **의심의 이익은 나그네에게.** 도착자의 문턱은 낮게, 검증의 무게는 **주는 쪽**에 싣는다. 위험은 집·차·돈이 오가는 자리에서 생긴다 |
| **신명기 24:19-21 · 룻기 2장** — 밭 모퉁이를 남겨 두라. 이삭은 본인이 와서 줍는다 | 심사받고 받아 가는 구조로 만들지 않는다. **열려 있는 것을 스스로 가져간다.** 애원하지 않아도 되게 |
| **누가복음 10:33-35** — 사마리아인은 신원을 묻지 않았고, 여관 주인에게 맡기며 비용을 댔다. 다만 "더 들면 갚겠다"였지 평생 보증은 아니었다 | 추천자는 소개만 하는 사람이 아니라 **짐을 조금 나누는 사람**. 그러나 책임 범위는 **유한하게 명시**한다 |
| **신명기 19:15 · 디모데전서 5:19** — 한 증인으로 정하지 말고 두세 증인으로 | **배제·제명 같은 무거운 판단은 두 사람 이상**의 확인이 있어야 한다. 신고 하나로 사람을 끊지 않는다 |
| **마태복음 18:15-17** — 단둘이 → 두세 사람 → 공동체 | 문제가 생기면 **조용히 먼저**. 즉시 공개 망신을 주는 기능을 만들지 않는다 |
| **야고보서 2:1-4** — 좋은 옷 입은 이에게 좋은 자리를 주지 말라 | **순서는 돈이 정하지 않는다.** 광고는 광고로 표시하되 순위를 사지 못한다 |
| **레위기 19:35-36 · 잠언 11:1** — 공정한 저울 | 「검증됨」은 **실제로 확인한 것만** 뜻한다. 확인하지 않은 것을 확인한 것처럼 보이게 하지 않는다 |
| **마태복음 18:12-14** — 아흔아홉을 두고 하나를 찾아간다 | **아무도 추천해 줄 사람이 없는 그 한 사람**을 위해 헤브론이 직접 나가 서명하는 문을 둔다. 효율로 설명되지 않는 문이다 |
| **히브리서 13:2** — 부지중에 천사를 대접한 이들이 있다 | 환대자에게 도착자의 신원을 **다 보여 주지 않는다.** 만나는 데 필요한 만큼만 |
| **마태복음 10:16** — 뱀처럼 지혜롭고 비둘기처럼 순결하게 | 안전을 위해 모은다(지혜). 그 자료로 **다른 일을 하지 않는다**(순결). 팔지도, 마케팅에 쓰지도 않는다 |

## 신원은 헤브론에게 밝힌다. 서로에게가 아니다

이것이 전체 설계의 열쇠다.

| | 헤브론에게 | 상대에게 | 세상에게 |
|---|---|---|---|
| **도착자** | 부를 이름 · 연락처 하나 · 아는 분 이름(있으면) | 이름과 연락처, **연결이 확정될 때만** | 아무것도 |
| **환대자** | 실명 · 연락처 · 추천인 · 무게에 따라 면허·보험·신원조회 | 이름과 연락처, **연결이 확정될 때만** | 이름과 도시까지만 |

**도착자에게 신분증·체류 신분·국적·종교·나이를 묻지 않는다.**
성경은 나그네 편에 서라고 했지 서류를 보라고 하지 않았다.
가장 절박한 사람이 못 들어오는 문이면 우리가 존재할 이유가 없다.

## 표 세 개

이 이상은 필요 없다. 늘리고 싶어질 때마다 이 문장을 다시 읽는다.

### `person` — 사람

| 칸 | 내용 |
|---|---|
| `id` | |
| `name` | 부를 이름. 실명일 필요 없음(도착자) / 실명(환대자) |
| `contact` | 하나만. 카카오톡 ID · 전화 · 이메일 중 |
| `city` | 도시 슬러그 |
| `role` | `arrive` · `host` · `both` |
| `status` | `new` · `checking` · `ready` · `paused` · `closed` |
| `entered_by` | 어느 문으로 들어왔나 (`arrive` · `open` · `vouch` · `hebron`) |
| `created_at` | |

### `vouch` — 추천

| 칸 | 내용 |
|---|---|
| `from_id` | 추천한 사람. 헤브론이 직접 서명하면 `hebron` |
| `to_id` | 추천받은 사람 |
| `relation` | 어떤 사이인가 (한 줄) |
| `note` | 하고 싶은 말 (한 줄) |
| `created_at` | |

한 사람에게 추천자는 **최대 둘**. 한 명이 떠나도 사슬이 끊기지 않게.

### `connection` — 연결

| 칸 | 내용 |
|---|---|
| `guest_id` · `host_id` | 누구와 누구를 |
| `introduced_by` | **누가 소개했는가.** 이 칸이 이 시스템의 심장이다 |
| `kind` | 길 안내 · 장보기 · 공항 · 밥 · 모임 · 잠자리 … |
| `state` | `offered` · `agreed` · `met` · `done` · `stopped` |
| `created_at` · `met_at` | |

## 검증 — 무게에 따라 다르게

주는 것이 무거울수록 확인이 깊다. 가벼운 것까지 무겁게 만들면 아무도 손을 들지 않는다.

| 무게 | 무엇 | 확인 |
|---|---|---|
| 0 | 길 안내 · 같이 장 보기 · 공항에서 만나기 · 모이는 자리 | 이름과 연락처. 통화 한 번 |
| 1 | 하는 일 소개 | + 추천인 한 명 |
| 2 | 차로 태워 주기 · 밥 한 끼 · 반려동물 | + 운전면허·보험 확인(차의 경우) · 추천인 한 명 |
| 3 | 잠자리 | + 대면 확인 · 추천인 두 명 · 신원 조회 |

**신청·문서·조회·승인 네 단계를 통과하지 않은 제공자는 연결하지 않는다.**
이것은 예외 없는 규칙이다.

## 아무도 없는 사람의 문

추천자가 없는 사람이 있다. 정작 우리가 존재하는 이유인 그 사람이다.

**헤브론이 직접 추천자가 된다.** 만나 보고 우리가 서명한다(`vouch.from_id = hebron`).
효율로 설명되지 않는 문이고, 이 문이 없으면 우리는 동호회가 된다.

이 문으로 들어온 사람은 표시가 남는다. 차별하기 위해서가 아니라,
**우리가 얼마나 그 한 사람을 찾아갔는지 세기 위해서**다.

---

## 연결이 이루어지는 순서

세 단계를 넘지 않는다.

```
1. 도착자가 남긴다        어느 도시 · 언제 · 무엇이 막막한지
2. 헤브론이 고른다        사람이 고른다. 자동으로 잇지 않는다
3. 양쪽에 묻고 잇는다     둘 다 좋다고 할 때만 연락처가 오간다
```

**자동 매칭을 하지 않는다.** 「검증된 사람의 소개를 받아」가 이 시스템의 이름이다.
기계가 이으면 그 순간 우리는 목록이 되고, 목록은 이미 세상에 많다.

---

## 절대 어기지 않을 셋

1. **관계망을 공개하지 않는다.** 누가 누구를 아는지는 우리 안에만 있다. 화면에도, 검색에도, AI에게도 내보내지 않는다.
2. **지워 달라면 지운다.** 이유를 묻지 않는다. 사람이 지워지면 그 사람의 추천과 연결도 함께 지워진다.
3. **추천은 보증이 아니다.** 「제가 아는 사람입니다」까지다. 이 선을 넘기면 아무도 손을 들지 않는다.

## 문제가 생겼을 때

마태복음 18:15-17의 순서를 그대로 따른다.

```
1. 조용히 먼저   당사자와 헤브론이 단둘이 확인한다
2. 두세 사람     해결되지 않으면 확인하는 사람을 늘린다
3. 배제          두 사람 이상의 확인이 있을 때만 끊는다 (신명기 19:15)
```

신고 한 건으로 사람을 끊지 않는다. 동시에, 안전이 걸린 일은 확인 전에 **연결을 멈춘다** —
끊는 것과 멈추는 것은 다르다.

---

## 만들지 않을 것

- **공개 평점·별점.** 사람에게 점수를 매기지 않는다
- **자동 매칭.** 사람이 고른다
- **관계망 시각화.** 누가 누구를 아는지 그림으로 그리지 않는다
- **추천 보상.** 돈이 걸리면 추천은 거래가 된다
- **즉시 신고·공개 고발 기능.** 조용히 먼저다

---

## 지금 상태와 첫 걸음

**이미 있는 것** — 「방금 도착하셨나요」(`arrive.html`)가 **「이 도시에 아는 분이 계신가요?」**를 묻고 있다.
지금은 글자로만 받는다. 그것이 사슬의 첫 고리다.

**첫 걸음** — 그 이름을 사람 기록에 **이어 둔다.** 표 세 개를 만들고, 지금 들어오는 신청을 거기에 쌓는다.

> ⚠️ `community_items` 한 표로는 안 된다. 없는 칸에 넣으면 **조용히 저장이 실패**한다
> (2026-07-23 사고 — [`reference_community_items_schema`]). 새 표가 필요하다.

## 변경 이력

### 2026-09-24 | 신뢰의 사슬 정립
- **무엇을**: 추천으로 이어지는 환대 구조를 정본으로 세움. 표 세 개(person·vouch·connection), 무게별 검증, 아무도 없는 사람의 문, 개인정보 절대 셋
- **왜**: 「검증된 사람의 소개를 받아 연결이 이루어져 환대를 받을 수 있게. 이 모든 관리를 헤브론이 하여 관계를 이어 간다」 — 폴 김 목사
- **교훈**: 성경이 이미 설계를 다 해 두었다. 우리가 발명할 것은 거의 없었다
